## 무엇이 문제인가

`check_sprites.py`는 통과하지만, 한 동작 안에 **다른 캐릭터처럼 보이는 프레임**이 섞여 있습니다. 걷는 동안 옷차림이나 체형이 깜빡이듯 바뀌어 보입니다.

**원인**: LOG에 따르면 앞쪽 끝 경고가 난 프레임을 **"기준 포즈 직접 편집 방식"** 으로 다시 만들었습니다. 코드로 그린 참고 그림을 바탕으로 그리면서 캐릭터 모델이 달라진 것입니다. 실제로 다시 만든 프레임이 0장인 **힙합은 완벽하게 일관적**이고, 16장·18장을 다시 만든 락킹·비보이가 가장 심합니다.

## 새 확인 도구: 비교 시트

눈으로 찾기 쉽도록 비교 시트 도구를 추가했습니다.

```bash
python3 scripts/contact_sheet.py locker walkF walkB crouch   # → shots/sheet_locker.png
```

채택된 대기 그림(`idle_0`)을 맨 앞에 두고 동작별로 한 줄씩 나란히 놓습니다. 대기 그림의 **머리 꼭대기(초록 선)** 와 **발밑(빨간 선)** 에 기준선이 그어져 있어서, 머리 크기·체형·옷차림이 튀는 프레임이 바로 보입니다. **커밋 전에 꼭 이 시트를 보고 확인하세요.**

## 다시 만들 때의 방법

- ❌ **참고 포즈 그림(코드 그림)을 직접 편집해서 만들지 않습니다.** 모델이 달라집니다.
- ✅ 앞쪽 끝 경고가 나면 **처음 생성한 그 캐릭터 그림을 편집**하거나 (팔·다리를 덜 뻗게), **채택된 대기 그림을 같은 격자에 함께 넣어** 다시 생성합니다.
- ✅ 한 격자로 생성한 묶음은 **같은 배율**로 맞춥니다: 격자 안에 채택된 그림(예: `idle_0`)을 한 칸 같이 그리게 하고, 그 칸을 `--ref`로 맞췄을 때 나온 배율을 나머지 칸에 `--scale`로 줍니다.

  ```bash
  python3 scripts/fit_sprite.py cell_idle.png /tmp/x.png --ref public/sprites/locker/idle_0.png   # "배율 0.83" 확인
  python3 scripts/fit_sprite.py cell_walkF_4.png public/sprites/locker/walkF_4.png --ref sprites-ref/locker/walkF_4.png --scale 0.83
  ```

- ✅ **크기 기준은 대기(idle)** 입니다. 가장 오래 보이는 그림이고 이미 채택되었습니다.
