# 디자인 작업 지시서 — DANCE BATTLE

> 이 문서만 읽고 작업을 시작할 수 있도록 썼습니다. 궁금한 점은 이슈로 남겨 주세요.
> 관련 문서: [SPRITES.md](../SPRITES.md) (그림 규격 원문), [CONTRIBUTING.md](../../CONTRIBUTING.md) (브랜치·PR 규칙)

## 0. 한 줄 요약

**캐릭터 스프라이트(동작별 키 포즈 그림)를 만드는 것이 이번 작업의 핵심입니다.** 배경·UI 그림은 그다음입니다.
먼저 **크럼프 한 명의 대기(8장) + 강P(6장)** 로 시범 작업을 해서 게임에 넣어 보고, 스타일이 확정되면 나머지로 넓힙니다.

---

## 1. 프로젝트 소개

- **DANCE BATTLE**: 8개 댄스 장르의 댄서가 장르 동작을 기술로 써서 싸우는 2D 대전 격투 게임입니다 (스트리트 파이터처럼 옆에서 보는 화면).
- 웹 브라우저 게임입니다 (TypeScript + Canvas). 화면 크기는 게임 좌표 960×540이고, 실제로는 2배(1920×1080)로 그립니다.
- 지금 캐릭터는 **코드로 그린 임시 그림**입니다 (`docs/design/reference/lineup.png`). 동작은 격투 게임처럼 **키 포즈 → 키 포즈로 끊어서** 보여 줍니다.
- 키 포즈마다 PNG를 넣으면 그 프레임은 그 그림으로 바뀝니다. 그림이 없는 프레임은 임시 그림이 나오므로 **조금씩 바꿔 나갈 수 있습니다.**

## 2. 이전 결과물에 대한 피드백

처음 만든 `stripe-neon-diagonal.png`(네온 사선 줄무늬 배경)는 필요한 에셋이 아니어서 삭제했습니다. 다음 작업에서 참고해 주세요.

- 이번에 필요한 것은 **캐릭터 스프라이트**입니다. 배경·장식은 4장의 2순위입니다.
- 에셋은 **정해진 규격**(크기, 투명 배경, 기준점, 파일 이름)을 지켜야 게임에 들어갑니다. 규격 없이 만든 그림은 쓸 수 없습니다.
- 반복해서 까는 텍스처라면 가장자리가 이어져야 합니다. 그 텍스처는 이음새 차이가 이웃 픽셀의 약 14배였습니다.
- 웹 게임이므로 용량을 지켜 주세요. 그 텍스처는 2.3MB였고, 목표는 한 장 300KB 이하입니다.

## 3. 1순위: 캐릭터 스프라이트

### 3-1. 그림 규격 (반드시 지켜 주세요)

| 항목      | 값                                                                                   |
| --------- | ------------------------------------------------------------------------------------ |
| 파일      | **PNG, 배경 투명**, 한 프레임 = 한 파일                                              |
| 크기      | **640 × 640 px**                                                                     |
| 방향      | 캐릭터가 **오른쪽을 보는** 모습 (왼쪽을 볼 때는 게임이 좌우를 뒤집습니다)            |
| 기준점    | 캐릭터 **발밑 중심이 (320, 580) px**. 참고 그림과 같은 위치에 서 있으면 됩니다       |
| 크기 비율 | 서 있을 때 키 약 380px (참고 그림과 같게)                                            |
| 용량      | 한 장 300KB 이하                                                                     |
| 이름      | `<동작id>_<프레임번호>.png` (예: `sHP_11.png`). **참고 그림과 똑같은 이름**을 씁니다 |
| P2 색     | (선택) `sHP_11_p2.png`. 없으면 게임이 P1 그림의 색을 자동으로 돌려서 씁니다          |

> 📌 **공중 동작**(`jump`, `airHit`, `jL`, `jH`)은 발밑이 아니라 캐릭터 위치가 기준점이라, 몸이 580px 아래로 내려가도 됩니다. 참고 그림 위치를 그대로 따르세요.

> ⚠️ **포즈와 손발 위치를 참고 그림과 맞춰 주세요.** 공격 판정(히트박스)이 참고 그림의 팔다리 위치에 맞춰져 있습니다. 주먹이 참고 그림보다 크게 짧거나 길면 "맞았는데 안 맞은 것처럼" 보입니다. 외곽선·옷 주름·표정 등 **디테일은 자유**입니다.

### 3-2. 아트 방향

- **스타일**: 2D 셀 셰이딩 카툰. 굵은 바깥 외곽선, 평면 색 + 그림자 한 단계, 필요하면 하이라이트 한 단계.
- **분위기**: 밤의 골목 댄스 배틀(사이퍼). 네온 조명, 스트리트 패션. 캐릭터는 어두운 배경 위에서 또렷이 보여야 합니다.
- **실루엣**: 8명이 **실루엣만으로도 구분**되어야 합니다 (모자, 머리 모양, 체격, 옷 품).
- **일관성**: 한 캐릭터의 모든 프레임에서 얼굴, 옷, 색, 비율이 같아야 합니다. 이게 가장 중요합니다.
- **동작 표현**: 격투 게임 스프라이트처럼 키 포즈를 과감하게. 옷자락·머리카락이 동작을 따라 휘날리고, 빠른 공격 자세에는 몸이 쭉 늘어나는 느낌을 줘도 좋습니다 (기준점과 손발 끝 위치만 유지).

### 3-4. 시범 작업 (먼저 이것만)

**크럼프(`krump`) P1 색으로 14장**을 만들어 주세요. 참고 그림은 이미 들어 있습니다: `docs/design/reference/krump/`

| 동작                     | 파일                                                                         | 설명                                                                                             |
| ------------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `idle` 대기 (반복)       | `idle_0` `idle_4` `idle_8` `idle_12` `idle_16` `idle_20` `idle_24` `idle_28` | 체스트 팝으로 리듬을 타는 대기. 8장이 이어져서 반복됩니다                                        |
| `sHP` 서서 강P "암 스윙" | `sHP_0` `sHP_4` `sHP_7` `sHP_11` `sHP_15` `sHP_24`                           | 0 시작 → 4·7 팔을 뒤로 젖히는 준비 → **11 휘두른 순간 (공격 판정)** → 15 따라 휘두름 → 24 돌아옴 |

함께 참고할 것:

- `docs/design/reference/lineup.png`: 8명 전체 (위 P1, 아래 P2)
- `docs/design/reference/krump_closeup.png`: 크럼프 크게 (왼쪽 P1, 오른쪽 P2)

**시범 작업 결과물**

1. 크럼프 설정 그림 1장 (옆모습 전신 + 색 표시). 모든 프레임의 기준이 됩니다.
2. 스프라이트 14장 (규격 3-1)
3. `public/sprites/krump/manifest.json` (아래 형식, `docs/design/reference/krump/manifest.example.json` 참고)

```json
{
  "frames": {
    "idle_0": { "p1": "idle_0.png" },
    "sHP_11": { "p1": "sHP_11.png" }
  }
}
```

### 3-5. 시범 이후 순서

시범이 확정되면 캐릭터마다 아래 순서로 진행합니다. 캐릭터 하나당 전체 약 150~240장입니다.

1. **기본 동작**: `idle` 대기, `walkF` 앞 걷기, `walkB` 뒤 걷기, `crouch` 앉기
2. **기본기**: `sLP` `sHP` `sLK` `sHK` (서서 약P·강P·약K·강K), `cLP` `cHP` `cLK` `cHK` (앉아서), `jL` `jH` (점프 공격)
3. **필살기·초필살기**: 캐릭터마다 다름 (연습 모드 기술 가이드나 캐릭터 선택 화면에서 이름 확인)
4. **공통 동작**: `prejump` `jump` `land` (점프), `hitStand` `hitCrouch` (맞음), `blockStand` `blockCrouch` (가드), `airHit` (띄워짐), `knockdown` (다운), `getup` (기상), `win` (승리)

동작 하나는 **모든 프레임을 한꺼번에** 바꿔 주세요. 절반만 바뀌면 임시 그림과 섞여 보입니다.

### 3-6. 참고 그림을 직접 뽑는 법 (개발 환경이 있을 때)

```bash
npm install
npm run dev                                         # 다른 터미널에서 켜 둔다
node scripts/export-sprites.mjs popper              # 팝핑의 모든 동작
node scripts/export-sprites.mjs popper idle wave    # 지정한 동작만
node scripts/export-sprites.mjs popper idle --p2    # P2 색도
```

결과는 `sprites-ref/<캐릭터>/`에 생깁니다 (커밋하지 않는 폴더). 개발 환경이 없으면 이슈로 필요한 캐릭터·동작을 요청해 주세요.

### 3-7. 이미지 생성 도구(Codex imagegen)로 작업하는 순서

생성된 이미지는 대개 크기·위치·배경이 규격과 다릅니다. **규격 맞추기 도구**와 **검사 도구**를 준비해 두었으니 아래 순서대로 쓰세요. (필요: Python 3 + Pillow, 이 컴퓨터에는 설치되어 있음)

1. **설정 그림부터**: 크럼프 옆모습 전신 설정 그림을 먼저 만들고 확정합니다 → `docs/design/krump_sheet.png`. 이후 모든 프레임 생성에 이 그림을 캐릭터 참고로 함께 넣습니다.
2. **프레임 생성**: 프레임마다 `docs/design/reference/krump/<이름>.png`를 **포즈 참고**로 넣어서 생성합니다.
   - 요청할 것: 전신이 잘리지 않게, 오른쪽을 보는 옆모습, **단색 배경**(예: 순수한 초록 `#00FF00`, 캐릭터에 쓰지 않는 색), 그림자·바닥·글자 없음
   - 투명 배경으로 바로 받을 수 있으면 그게 가장 좋습니다
   - 생성 원본은 `sprites-work/krump/`(커밋하지 않는 폴더)에 둡니다
3. **규격 맞추기**: 배경을 지우고, 참고 그림과 같은 키·발밑·위치로 640×640에 배치합니다.

   ```bash
   python3 scripts/fit_sprite.py sprites-work/krump/idle_0.png public/sprites/krump/idle_0.png \
     --ref docs/design/reference/krump/idle_0.png
   ```

   - 캐릭터가 왼쪽을 보고 있으면 `--flip`, 배경색이 균일하지 않아 덜 지워지면 `--key "#00ff00" --tol 70`
   - 결과를 눈으로 확인하세요. 배경이 남았거나 캐릭터 일부가 지워졌으면 생성부터 다시 하는 게 빠릅니다.

4. **목록 파일**: `public/sprites/krump/manifest.json`에 넣은 프레임을 모두 적습니다 (`docs/design/reference/krump/manifest.example.json`을 복사하면 14장이 이미 적혀 있음).
5. **검사**: 아래 명령에서 ❌가 없어야 합니다. ⚠️는 확인 후 괜찮으면 두어도 됩니다.

   ```bash
   python3 scripts/check_sprites.py krump
   ```

6. **게임에서 확인**: 개발 서버(`npm run dev`, http://localhost:5173)에서 트레이닝 → 크럼프 선택 → 대기 모습 보기, 강P(G키) 눌러 보기. **F1**로 판정 박스를 켜서 팔 위치가 맞는지 봅니다.

**일관성이 가장 어렵습니다.** 프레임을 하나씩 따로 만들면 얼굴·옷이 조금씩 달라집니다. 매번 설정 그림과 같은 설명 문구를 함께 넣고, 한 동작의 프레임은 한 번에 이어서 만드세요. 크게 달라진 프레임은 다시 생성합니다.

## 4. 2순위: 무대 · UI · 이펙트

## 5. 작업 방법

이 저장소 폴더(`GameProject`)에서 바로 작업합니다. 따로 받을(clone/pull) 필요는 없습니다.

1. 작업 브랜치는 **`art/krump-pilot`** 입니다 (미리 만들어 두었음). `git branch --show-current`로 확인하세요.
   - 다른 캐릭터·동작을 시작할 때는 새 브랜치를 만듭니다: `art/<캐릭터>-<내용>`
2. **다른 에이전트(개발 담당)와 같은 폴더를 동시에 쓰지 않습니다.** 작업 중에는 `src/` 등 코드 파일을 고치지 마세요. 코드 수정이 필요하면 이슈나 메모로 남겨 주세요.
3. **완성된 그림만** 커밋합니다: `public/sprites/<캐릭터>/`, `docs/design/<캐릭터>_sheet.png`
   - 커밋하지 않는 것: `sprites-ref/`(내보낸 참고 그림), `sprites-work/`(생성 원본), `shots/`
4. 커밋 전에 `python3 scripts/check_sprites.py <캐릭터>`와 `npm run check`가 통과해야 합니다.
5. 커밋 메시지 예: `art: 크럼프 대기·강P 스프라이트 14장 (시범)`
6. 작업이 끝나면 결과 요약(만든 파일, 사용한 도구, 검사 결과, 게임 화면 스크린샷)을 남겨 주세요. 푸시와 PR은 사용자가 결정합니다.

## 6. 검수 기준 (PR 체크리스트)

- [ ] `python3 scripts/check_sprites.py <캐릭터>`에 ❌ 없음
- [ ] 640×640, 배경 투명, 한 장 300KB 이하
- [ ] 오른쪽을 보는 모습, 발밑 중심이 (320, 580) px (참고 그림과 ±4px 이내)
- [ ] 파일 이름이 참고 그림과 똑같고, `manifest.json`에 모두 적혀 있음
- [ ] 공격 프레임의 주먹·발끝이 참고 그림 위치와 비슷함 (F1 판정 박스로 확인)
- [ ] 한 동작의 모든 프레임이 들어 있음
- [ ] 모든 프레임에서 얼굴·옷·색·비율이 같음
- [ ] 어두운 무대 배경 위에서 캐릭터가 또렷이 보임
- [ ] 글자, 워터마크, 서명 없음

## 7. AI 이미지 도구를 쓸 때

- **설정 그림을 먼저 확정**하고, 모든 프레임에 같은 설정을 참고로 넣어 일관성을 지켜 주세요. 프레임마다 얼굴이나 옷이 달라지는 게 가장 흔한 문제입니다.
- 참고 그림을 **포즈 가이드**(img2img, 포즈 컨트롤 등)로 쓰면 포즈와 위치를 맞추기 쉽습니다.
- 결과물은 배경을 지우고 640×640 캔버스의 기준점에 맞춰 다시 배치해 주세요. 생성된 그대로는 크기와 위치가 맞지 않는 경우가 많습니다.
- **공개 저장소에 올라갑니다.** 도구의 상업적 이용·재배포 조건을 확인하고, 조건이 불분명한 도구는 쓰지 마세요.
- 실존 인물, 유명 댄서, 다른 게임 캐릭터를 닮게 만들지 마세요.
