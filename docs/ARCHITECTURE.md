# 구조 설명

DANCE BATTLE의 코드가 어떻게 나뉘어 있고, 한 프레임 동안 무슨 일이 일어나는지 설명합니다.

## 폴더 구조

```
src/
├── main.ts          시작점. 60fps 루프, 화면 전환 (타이틀 → 캐릭터 선택 → 대전)
├── core/            상수(화면 크기, 중력, 라운드 시간), 수학 유틸
├── input/
│   ├── devices.ts       키보드/게임패드 읽기, 키 배치, 메뉴 입력
│   ├── inputBuffer.ts   프레임 단위 입력 기록 → 커맨드(↓↘→) 인식, 선입력
│   └── types.ts         버튼·방향 정의
├── anim/pose.ts     스틱맨 뼈대, 포즈 → 관절 위치 계산, 키프레임 보간, 지면 스냅
├── fighter/
│   ├── types.ts         기술(MoveDef)·캐릭터(CharacterDef) 데이터 형식  ← 공용 파일
│   └── fighter.ts       캐릭터 상태 머신 (이동, 점프, 기술, 피격, 가드, 다운)
├── characters/
│   ├── index.ts         캐릭터 목록(CHARACTERS), 기술표 생성
│   ├── common.ts        모든 캐릭터가 같이 쓰는 동작 (피격, 가드, 점프, 다운, 기상)
│   ├── builders.ts      기술 데이터를 짧게 쓰는 도우미 (strike, combo, shooter...)
│   └── <캐릭터>/        poses.ts(자세·동작) · moves.ts(기술) · index.ts(외형·스탯·커맨드)
├── game/
│   ├── match.ts         한 판의 대전 (라운드, 타이머, 트레이닝 모드)
│   ├── combat.ts        타격 판정, 가드, 아머, 반격, 장풍, 밀어내기
│   ├── events.ts        로직 → 렌더러로 보내는 이벤트
│   └── match.test.ts    로직 테스트
├── screens/select.ts 캐릭터 선택 화면
├── training/guide.ts 연습 모드 기술 가이드: 성공 판정, 커맨드 시범 입력 생성
├── render/
│   ├── dancer.ts        캐릭터 그리기: 스켈레톤을 따라 부위·의상·얼굴·모자를 그린다
│   ├── dynamics.ts      머리카락·끈 흔들림, 공격 궤적 (연출 전용)
│   ├── sprites.ts       교체 그림(스프라이트) 불러오기·그리기
│   ├── assets.ts        무대 배경·로고·초상화·타격 이펙트 그림 불러오기 (없으면 코드 그림)
│   ├── renderer.ts      대전 화면 조립 (무대 → 관중 → 캐릭터 → 장풍 → 이펙트 → HUD)
│   └── stage.ts, hud.ts, effects.ts, guideHud.ts
├── audio/sfx.ts     Web Audio로 합성하는 효과음
└── debug/gallery.ts 동작 확인용 갤러리 페이지
```

## 두 개의 층: 로직과 그리기

```
 입력 ──▶ [ 게임 로직 ]  ──이벤트──▶ [ 그리기 · 소리 ]
          game/ fighter/            render/ audio/
          characters/ input/
          (결정론, 60fps 고정)       (자유롭게, 로직을 읽기만 함)
```

- **게임 로직**은 화면을 전혀 모릅니다. 캔버스, DOM, 오디오를 쓰지 않아요. 그래서 브라우저 없이 테스트할 수 있습니다.
- **그리기 쪽**은 로직의 상태(`Match`, `Fighter`)를 읽기만 하고 절대 바꾸지 않습니다.
- 로직에서 연출이 필요하면(타격 이펙트, 효과음, "COUNTER!" 글자) `GameEvent`를 `match.events`에 넣습니다. 렌더러가 매 프레임 이벤트를 받아서 이펙트와 소리를 냅니다.

이렇게 나눠 둔 덕분에, 나중에 **2.5D/3D로 바꿀 때는 `render/`만 새로 만들면 됩니다.** 로직과 캐릭터 데이터는 그대로 씁니다.
실제로 스틱맨 → 퍼펫 그래픽 교체도 `render/`만 바꿔서 했습니다.

### 그래픽 발전 경로

1. **지금: 코드로 그리는 퍼펫** (`dancer.ts`). 부위를 따로 그린 뒤 몸 전체 실루엣에만 바깥 테두리를 두르고, 무릎·팔꿈치에 옷 주름을 넣는다. 동작은 키 포즈 단위로 끊어서 보여 준다 (`displayFrame`).
2. **스프라이트 교체**: 키 포즈마다 그림(PNG)을 넣으면 그 프레임은 그림으로 나온다 (`render/sprites.ts`). 한 장씩 점진적으로 바꿀 수 있다. → [SPRITES.md](SPRITES.md)
3. **3D**: Three.js 등으로 3D 모델을 두고, 같은 `Match` 상태를 읽어 그린다. 춤 동작은 3D 애니메이션 클립이 필요하다.

화면은 게임 좌표(960×540)로 그리고, 캔버스는 2배 해상도(`RENDER_SCALE`)로 만들어서 크게 띄워도 선명하다.

## 한 프레임에 일어나는 일

`main.ts`는 브라우저 화면 갱신과 상관없이 **정확히 60번/초** 로직을 돌립니다(고정 타임스텝). 그리기는 브라우저 화면 갱신마다 따로 합니다.

`Match.update()` 한 번의 순서:

1. **입력 기록**: 두 플레이어의 입력을 각자의 `InputBuffer`에 넣는다 (캐릭터가 보는 방향 기준으로 변환)
2. **초필살기 정지 중이면 여기서 끝** (연출 동안 로직 전체 일시정지)
3. **캐릭터 업데이트**: `Fighter.update()`
   - 히트스톱(타격 경직) 중이면 멈춤. 이때 들어온 캔슬 커맨드는 예약해 뒀다가 경직이 풀리면 발동
   - 상태별 처리: 대기/걷기에서 입력 → 기술 시작, 기술 진행(프레임 +1, 이동, 캔슬), 피격 경직 감소, 공중 물리 등
4. **장풍 생성, 초필살기 정지 시작**
5. **밀어내기**: 두 캐릭터가 겹치지 않게
6. **타격 판정**: 양쪽 공격을 먼저 다 찾은 뒤 적용 (동시에 맞으면 둘 다 맞음)
7. **장풍 이동과 판정**: 장풍끼리 상쇄 → 상대 적중
8. **방향 전환**: 대기·걷기 중일 때만 상대 쪽을 보도록
9. **콤보 표시, 라운드 진행** (KO, 타임오버, 다음 라운드)

## 캐릭터 상태 머신

`Fighter.state`가 가질 수 있는 값:

```
idle ⇄ walkF / walkB / crouch          (조작 가능)
  │ ↑
  ├─▶ prejump ─▶ jump ─▶ land ─▶ idle
  ├─▶ move (기술 사용 중) ─▶ idle / crouch
  │
  ├─▶ hitstun / blockstun ─▶ idle        (피격 / 가드 경직)
  └─▶ airHit (띄워짐) ─▶ knockdown ─▶ getup ─▶ idle
                                    └▶ ko (체력 0)
win (라운드 승리 포즈)
```

## 타격이 처리되는 순서

공격 판정(빨강)이 맞는 판정(초록)에 닿으면 `combat.ts`의 `applyContact()`가 아래 순서로 결정합니다.

1. **반격(프리즈)**: 맞는 쪽이 반격 자세 중이면 반격기가 나간다 (초필살기에는 안 통함)
2. **가드**: `unblockable`이 아니고, 방향을 맞게 잡고 있으면 가드
   - 하단(`low`)은 앉아서만, 중단(`overhead`)은 서서만, 일반(`mid`)은 둘 다 막을 수 있다
   - 가드해도 필살기는 `chip` 만큼 깎인다 (가드 데미지로는 KO되지 않음)
3. **슈퍼아머**: `armor` 구간이면 데미지만 받고 기술은 계속된다 (1회, 초필살기에는 깨짐)
4. **적중**
   - 콤보 보정: 같은 콤보에서 한 대 맞을 때마다 데미지 10%씩 감소 (최소 30%)
   - `launch` / `knockdown` 이거나 공중에 있으면 → 띄워짐(`airHit`), 아니면 → 피격 경직(`hitstun`)
   - 공중 콤보는 4히트까지 (그 뒤로는 무적)
   - 게이지: 때린 쪽은 데미지의 1/8, 맞은 쪽은 1/16을 얻는다

## 입력과 커맨드 인식

- 입력은 매 프레임 `InputBuffer`에 **넘패드 방향**(1~9, 6 = 앞, 4 = 뒤)으로 기록됩니다. 캐릭터가 왼쪽을 보면 좌우가 뒤집혀 기록돼요.
- 커맨드 인식: 최근 N프레임 안에 방향이 순서대로 있었는지 확인합니다.
  - `↓↘→` (qcf), `↓↙←` (qcb): 16프레임 안에
  - `→↓↘` (dp): 14프레임 안에
  - 초필살기 `↓↘→↓↘→`: 36프레임 안에
- **선입력**: 버튼은 5프레임 전에 눌렀어도 인정합니다. 한 번 기술에 쓴 입력은 소비되어 다시 쓰이지 않아요.
- **우선순위**: 초필살기 → 필살기(캐릭터 `specials`에 적힌 순서) → 기본기. 여러 버튼을 동시에 누르면 강한 버튼이 우선입니다.

## 연습 모드 커맨드 시범

시범은 **가짜 입력을 넣는 방식**입니다. `TrainingGuide.startDemo()`가 선택한 기술의 커맨드를 프레임 단위 입력 목록(↓ 4프레임 → ↘ 4프레임 → → 4프레임 + 버튼...)으로 만들고, 시범 동안 `main.ts`가 키보드 대신 그 입력을 P1에게 넣습니다.
게임 로직 입장에서는 사람이 누른 것과 똑같아서, 시범이 되면 실제로도 그 커맨드로 기술이 나간다는 뜻입니다. `guide.test.ts`가 모든 캐릭터의 모든 기술 시범을 돌려서 확인합니다.

## 결정론 규칙

**같은 입력을 넣으면 언제 어디서 돌려도 똑같은 결과가 나와야 합니다.** 이게 지켜져야 테스트가 믿을 만하고, 나중에 온라인 대전(롤백 넷코드)이나 리플레이를 만들 수 있어요.

다음 폴더/파일에서는 **무작위와 현재 시각을 쓰지 않습니다**:
`src/game/`, `src/fighter/`, `src/characters/`, `src/anim/`, `src/core/`, `src/input/inputBuffer.ts`, `src/input/types.ts`, `src/training/guide.ts`

| 쓰면 안 되는 것                                 | 대신                                                                                        |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `Math.random()`                                 | 무작위가 꼭 필요하면 시드가 있는 난수 생성기를 `Match`에 두고 공유 (필요해지면 이슈로 논의) |
| `Date.now()`, `performance.now()`, `new Date()` | 시간은 전부 **프레임 수**로 센다 (`stateFrame`, `moveFrame`, `phaseFrame`)                  |
| `setTimeout`, `setInterval`                     | 프레임 카운터로 "N프레임 뒤"를 구현                                                         |

`npm run check:determinism`이 이 규칙을 자동으로 검사하고, CI에서도 돌아갑니다.
연출 쪽(`render/`, `audio/`)은 무작위를 써도 됩니다. 예를 들어 타격 이펙트의 불꽃 방향이 그렇습니다.

## 좌표계

- **월드 좌표**: x는 오른쪽 +, y는 **위쪽 +**, 바닥은 y = 0. 무대는 x = 40 ~ 920.
- **캐릭터 기준 좌표** (히트박스, 포즈): x는 **캐릭터가 보는 방향이 +**. 왼쪽을 보는 캐릭터는 자동으로 뒤집혀요.
- 화면에 그릴 때만 `화면 y = 470 - 월드 y`로 바꿉니다 (`GROUND_SCREEN_Y`).
