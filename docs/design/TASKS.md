# 디자인 작업 목록

> 디자인 에이전트는 이 목록을 **위에서부터 순서대로** 진행합니다. 한 작업을 끝낼 때마다 커밋하고, 아래 "진행 기록" 규칙대로 남긴 뒤 다음 작업으로 넘어갑니다.
> 기준 문서: [DESIGN_BRIEF.md](DESIGN_BRIEF.md) (규격·아트 방향·캐릭터 설정), [REVIEW_krump_pilot.md](REVIEW_krump_pilot.md) (시범 검토)

## 공통 규칙 (모든 작업)

1. **참고 그림은 직접 내보냅니다.** 개발 서버(`npm run dev`, 보통 http://localhost:5173)를 켜고:
   ```bash
   node scripts/export-sprites.mjs krump walkF walkB crouch   # 작업할 동작만
   ```
   결과는 `sprites-ref/krump/`에 생깁니다 (커밋하지 않음). 규격 맞추기에도 이 참고 그림을 씁니다:
   ```bash
   python3 scripts/fit_sprite.py sprites-work/krump/walkF_0.png public/sprites/krump/walkF_0.png --ref sprites-ref/krump/walkF_0.png
   ```
2. **참고 그림에서는 포즈와 위치만 따릅니다.** 얼굴, 머리띠·모자 위치, 머리카락, 옷 디테일은 **설정 그림**(`docs/design/<캐릭터>_sheet.png`)과 브리프를 따르세요. 참고 그림은 코드로 그린 임시 그림이라 디테일이 어색한 곳이 있습니다 (예: 전에는 머리띠가 눈을 가렸음).
3. **완료 기준**
   - `python3 scripts/check_sprites.py <캐릭터>`에 **❌와 ⚠️가 모두 없음** (앞쪽 끝 ±20px 포함)
   - 한 동작의 **모든 프레임**이 들어 있고, `public/sprites/<캐릭터>/manifest.json`에 모두 적혀 있음
   - 설정 그림과 얼굴·옷·색·비율이 같음
   - `npm run check` 통과
   - **실제 게임에서 확인** (각 작업의 "확인 방법"). 갤러리 화면은 교체 그림을 보여 주지 않으니 확인용으로 쓰지 마세요.
4. **동작 하나는 한꺼번에** 교체합니다. 절반만 넣지 마세요.
5. **코드(`src/`)는 고치지 않습니다.** 필요하면 진행 기록에 메모합니다.
6. **푸시하지 않습니다.** 커밋까지만 합니다.
7. **그림을 가로나 세로로만 늘이거나 줄이지 않습니다.** 크기 조절은 `fit_sprite.py`의 균일 배율만 씁니다. 앞쪽 끝 ⚠️가 나면 폭을 억지로 맞추지 말고 **다시 생성**하세요 (2차 검토에서 찌그러진 그림이 나왔음).
8. **격자로 한 번에 생성할 때는 칸 사이 여백을 넉넉히** 두세요. 잘라 낼 때 옆 칸이 딸려 오면 `check_sprites`가 ❌(떨어진 조각)로 잡습니다.
9. **색은 설정 그림의 색 코드와 대조**하세요. P1 그림에 P2 색이 섞이지 않게 합니다. `check_sprites`가 프레임끼리 옷 색이 다르면 ❌로 잡습니다.

### 진행 기록

작업을 하나 끝낼 때마다:

- 이 문서의 해당 작업 체크박스를 `[x]`로 바꿉니다.
- [LOG.md](LOG.md) 맨 아래에 한 단락을 추가합니다: 작업 번호, 만든 파일 수, `check_sprites` 결과, 다시 만든 프레임과 이유, 남은 문제.
- 커밋 메시지: `art: <작업 번호> <내용>` (예: `art: T2 크럼프 걷기·앉기 30장`)

### 검토 지점 🛑

🛑 표시가 있는 작업이 끝나면, 사용자가 확인할 수 있도록 LOG에 **"검토 요청"** 이라고 적습니다. 그다음 작업은 계속 진행해도 되지만, 검토 결과에 따라 다시 만들 수 있다는 점을 감안하세요.

| ---------------------- | ----------------------------- | -------------------- |

- `knockdown`은 등으로 누운 자세, `getup`은 옆으로 굴러 일어나는 동작입니다.
